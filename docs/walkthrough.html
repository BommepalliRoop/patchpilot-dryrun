PatchPilot, step by step

A client gives us one thing: a GitHub repository, in any language. PatchPilot finds the vulnerable libraries, proves which ones the code really calls, fixes them with tested upgrades, opens a pull request, and Boomi files the Jira ticket, Slack alert and audit record. Automatically, every day.

  5. 4
    STAGE 1 · clone

    Download the code into a temporary folder

    A shallow copy of the branch goes into a throwaway work folder. The GitHub token is used only for private repos and never shows up in logs.

  6. 5
    STAGE 2 · scan

    Detect languages, then find vulnerable libraries with OSV

    PatchPilot finds every dependency file (here: Python and JavaScript). OSV-Scanner checks every pinned version against Google's open vulnerability database. Each CVE is then tagged with exploit data: is it on the US CISA list of actively exploited CVEs, and what is its EPSS chance of being exploited?

    # requirements.txt (demo repo) flask==1.1.2 2 CVEs werkzeug==1.0.1 10 CVEs jinja2==2.11.2 5 CVEs pyyaml==5.3.1 CVE-2020-14343 · CVSS 9.8 · EPSS top 7% requests==2.25.1 4 CVEs urllib3==1.26.4 11 CVEs # tools/package-lock.json (JavaScript) lodash 4.17.15 6 CVEs, incl. CVE-2021-23337 command injection → about 35 alerts in total
  7. 6
    STAGE 3 · symbols · AI

    AI names the dangerous function

    For each advisory, the AI reads the description and returns the exact function that is unsafe, for example yaml.load for CVE-2020-14343. Answers are checked JSON; if the AI is unavailable, a built-in map is used.

  8. 7
    STAGE 4 · reachability · code analysis + AI

    Prove whether our code really calls it

    Python's own parser walks every file, follows imports and aliases, and finds each call to the dangerous function, with file, line and whether it sits inside a web route. The AI then checks the snippet for safe usage. No call found means not reachable, with no AI call at all.

    # app/routes.py @app.route("/import", methods=["POST"]) ← web route def import_config(): data = yaml.load(request.data) ← line 42: user input reaches yaml.load return save(data)
    reachable · confidence 0.93in web routedeep analysis

    Other languages (JavaScript, Java, Go, …): PatchPilot searches the source for imports of the package and for the dangerous function name, then the AI judges the snippets. If the package is never imported, it is a hidden dependency and marked not reachable.

    // tools/report.js const _ = require('lodash'); const html = _.template(userTemplate)(data); ← lodash _.template with user input
    reachable · confidence 0.8text + AI analysis
  9. 8
    STAGE 5 · risk

    Score the real risk

    score = CVSS × reachability × exposure × exploit data (max 10)
    FactorValues
    Reachabilityreachable 1.0 · unsure 0.6 · not reachable 0.3
    Exposureinside a web route 1.5 · otherwise 1.0
    Exploit dataon CISA KEV list 1.3 · EPSS top 10% 1.1 · otherwise 1.0
    Priority≥ 9 P1 · ≥ 7 P2 · ≥ 4 P3 · else P4

    PyYAML: 9.8 × 1.0 × 1.5 × 1.1 → capped at 10 → P1.

  10. 9
    STAGE 6 · fix · once per package

    Upgrade, test, and let AI repair what breaks

    Upgradepyyaml 5.3.1 → 6.0.1 · lodash 4.17.15 → 4.18.0
    Install + testpytest or npm test in a temp folder, no secrets, no install scripts
    Tests fail?AI writes a small patch, max 2 tries
    Resultfixed, or needs review

    Several CVEs in the same package get one fix and one PR. The AI patch may only touch the files involved, never the tests. For languages whose tools are not installed, PatchPilot still opens the upgrade PR, clearly marked "tests not run".

  11. 10
    STAGE 7 · pr

    Open a pull request on GitHub

    Branch patchpilot/pyyaml-6.0.1, title [PatchPilot][P1] Fix CVE-2020-14343 in pyyaml, and a body that explains why it was reachable, what changed and that tests passed. The client's developers review and merge it. PatchPilot never merges on its own.

  12. 11
    STAGE 8 · notify · Boomi team

    Boomi files the ticket, alert and audit record

    PatchPilot→ B2 → Jira issue SEC-101 Slack alert Compliance row (Supabase)

    At the end of the scan, B3 posts one summary card to Slack. If Boomi is down, the scan still finishes and the failed call is shown in the app.
